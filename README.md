# Codex Model Bar

The toolbar reads live model titles every 250 ms while Codex is frontmost, but reuses attached composer controls for up to five seconds. Focus changes, actions and detached controls force discovery immediately. A missing composer backs off to one full walk per second. Embedded browser trees are excluded, and each AX queue work item drains its temporary Cocoa objects. The bounded diagnostic log records scan node counts and duration, plus this process's current/peak memory footprint once a minute, without chat or draft text.


**Models, reasoning and speed beside Codex.** The toolbar keeps its normal position while clear. If Agent Flow covers that position, it compares free space around both Codex and every Flow panel, switching sides or moving above/below instead of covering their content. It stays near Codex’s bottom edge, keeping a horizontal row when that fits nearby and wrapping when the clear space requires it.

[Project page](https://ethansk.github.io/codex-model-bar/) · [Source](https://github.com/EthanSK/codex-model-bar) · [Claude in Codex](https://github.com/EthanSK/claude-in-codex)

The overlap check always uses the normal full-width toolbar position, so moving beside Flow does not make it alternate back and forth. Separate or mirrored HUDs that do not cover that position leave it alone. Moving or shrinking Flow clear restores the normal strip. A brief main-window lookup gap keeps the already identified, still-visible task window instead of hiding the toolbar; a ready replacement takes over directly. Flow or the toolbar's own accessory can temporarily take focus from Codex without hiding the controls. Switching to an unrelated app hides them, including when Flow's mirrored HUDs remain visible. The normal toolbar sits below Codex or above it when there is no room below. If no clear region can contain readable controls, such as when Codex fills the whole display, the existing visible top-edge fallback remains; zero overlap is impossible on that display in that case. It follows Codex's main task window rather than floating computer-use previews.

## Install

[Download the signed macOS app](https://github.com/EthanSK/codex-model-bar/releases/latest/download/CodexModelBar-macOS-universal.zip). Unzip it and move Codex Model Bar to Applications. The universal download supports Apple silicon and Intel Macs on macOS 13 or newer and is signed with Developer ID and notarized by Apple. Grant Accessibility access when macOS asks. Switching from a development build may require enabling the signed app in Accessibility again; existing preferences stay on your Mac.

Right-click the toolbar for **Check for updates…** and the automatic check/download controls. Checks run daily by default while the app is open. Sparkle verifies signed downloads and uses its standard update dialogs. An update waits for any model, reasoning or speed action to finish before restarting the bar.

## Install from source

You need **macOS 13 or later**, the **Codex desktop app**, and **Xcode Command Line Tools** (`xcode-select --install`). The source build below is an alternative to the signed download.

```sh
git clone https://github.com/EthanSK/codex-model-bar.git
cd codex-model-bar
swift test --scratch-path .build.noindex
./scripts/build-app.sh
```

The script builds a release app for your Mac, signs it, installs it at `~/Applications/Codex Model Bar.app`, and opens it. On first launch, grant **Accessibility** access when macOS asks. If the prompt does not appear, use **System Settings → Privacy & Security → Accessibility** and enable Codex Model Bar. The app needs that access to find the open task's composer and operate Codex's model menu.

The script prefers an available Developer ID Application identity, matching the public releases, then Apple Development, then ad-hoc signing. Changing signing families or using an ad-hoc rebuild may need a fresh Accessibility grant. An enabled Accessibility row can still refer to the old signing identity; remove that stale row and add the current installed app in System Settings. Set `CODEX_MODEL_BAR_SIGN_ID` to a specific signing identity if you have more than one. Use `./scripts/build-app.sh --no-install` to build `build.noindex/Codex Model Bar.app` without replacing the installed copy. Generated apps, icon files and rollback copies stay under `build.noindex/`; SwiftPM uses `.build.noindex/`, so these derived folders stay out of Spotlight. Existing `build/` and `.build/` folders are left in place. Set `CODEX_MODEL_BAR_BUILD_ROOT` to a mounted scratch directory to put both generated folders there instead of inside the source checkout. `CODEX_MODEL_BAR_ARCH` can override the detected `arm64` or `x86_64` build architecture, or use `universal` for both.

## Use

Click a model in the strip to change the **open Codex task**. The reasoning slider changes its reasoning level; each tick is one level supported by the current model. Its label previews the selected level while you drag, and the bar applies that level when you release. The toolbar keeps the same size as model selection and reasoning levels change. Right-click the strip to show or hide model buttons, refresh the list, turn **Open at login** on or off, or quit. Open at login is enabled on the first installed launch; you can disable it from the same menu. Hidden buttons are your local choice and do not remove models from Codex itself.

Keep the controls close to Codex’s bottom edge and below it where possible. When Agent Flow covers that space, try the free space beside Flow before sending the bar far above Codex. A nearby wrapped bar is more useful than a distant horizontal row; among equally close placements, keep the fewest rows, then prefer Flow’s right side. Placement removes both Codex and all detected Flow panels from the available screen space. Controls retain their readable sizes; regions too narrow for even one control are rejected. The reasoning label and slider stay together unless even that group cannot fit. Floating notices use the same window bounds, so a message beside a left-hand bar cannot spill back over Codex. As soon as the normal position is clear, including while a HUD shrinks before disappearing, the bar returns directly beneath Codex. The four-point spacing around Flow only applies while choosing an alternative position; it cannot keep a clear normal position blocked. The tracker reuses its existing window-list scan and known IDs; it does not read Agent Flow input, move its windows or start another timer. Foreground state updates on the existing fast follow timer.

With a main task and side task open, the bar follows the input you have focused, or the unique composer inside the focused Conversation region after a body click. That region takes precedence over the previously used chat, including when Chromium omits parent links; a loading or ambiguous clicked pane does not fall back to the other chat. Model actions resolve that input before activating Codex, then focus it without moving the draft selection, even when the requested model is already selected. The existing cache also refreshes when focus moves between those regions. The bar follows changes made with Codex's own picker. If it cannot identify the active composer, a model switch stops instead of choosing the first input in the window; speed and reasoning wait up to 1.5 seconds for Codex to remount its composer, then send to whatever Codex has focused. Moving to another input during a reasoning drag cancels that drag. Status messages float outside the toolbar, on its right when there is room and above or below it at the screen edge. They never replace the reasoning label or slider, and disappear when the toolbar hides. A completed notice leaves the controls available immediately; only an action still in progress keeps its existing input lock.

Ordinary model and reasoning actions finish when the final key is posted. The existing background watcher updates the strip from Codex's actual model and effort; posting keys does not fabricate a successful selection. There is no final model confirmation, draft wait or post-choice Backspace cleanup, and no background confirmation check. **The bar never verifies a sent action; it sends its best attempt and assumes it worked** (Ethan, 2026-10-29).

The reasoning slider uses Codex's **Increase reasoning effort** and **Decrease reasoning effort** commands. Assign both shortcuts in Codex's keyboard shortcut settings; the bar reads `~/.codex/keybindings.json` and only sends a shortcut that is actually configured. For example, assign `Ctrl+Command+Up` to increase and `Ctrl+Command+Down` to decrease. Disabled shortcut entries are ignored when reading the file. It reads the starting effort to calculate the number of presses. Reasoning uses the speed buttons' input targeting and focus handoff before reading model/effort controls, including when Agent Flow owns the keyboard or the requested effort is already selected. It preserves the draft selection, then reads the current level once to count presses. From 1.2.60 that read reuses the model button the background poll already paired with the input just focused, instead of always walking the whole window again; another pane's pair or a missing button still forces the fresh walk. Focus returns to the captured typing input only if no newer user action superseded the handoff. For a jump of several levels, presses are spaced 150 ms apart without waiting for Codex to confirm each level. Codex's relative command uses the currently rendered value, so under heavy lag a jump can land one level short. If the shortcuts are missing or the composer does not report an effort, the slider cannot change it.

The buttons use model entries observed in Codex's shared cache. If you use [Claude in Codex](https://github.com/EthanSK/claude-in-codex), its Claude entries appear too. That cache can briefly omit models the desktop still offers, so refreshes preserve previously known entries and their button order. Updated names, reasoning levels and explicit hidden flags still apply. The saved list also survives a bar restart; hide an unwanted button from the right-click menu. Keeping a button does not guarantee account access: a switch still requires Codex's menu to offer the model. The bar can ask Codex's bundled `app-server` when the shared cache is unavailable, and you can refresh manually from the right-click menu.

The switcher uses Codex's inline `/model` menu, with the shared 100 ms pre-typing pause, 8 ms character spacing and 37.5 ms post-typing gap. All text routes first focus the intended chat input through the shared focus helper; from 1.2.64 model search and the separate combined model/Ultrafast action also wait the same 100 ms before typing as normal speed commands. It recognises the typing menu when Codex renders it separately from the message box, restricted to the focused composer’s own web area. To switch, the bar opens the menu with Control+Command+M, searches by model id, waits once until every result names the target model, then presses Return and finishes. It checks keyboard ownership at the typing boundaries and watches hardware input during the search, without repeating Accessibility focus reads for every character. If a floating typing panel takes keyboard focus during a switch, the bar restores Codex's focus and retries once only when the same composer and its unchanged draft can be verified. It stops if you type or click, and an abandoned search removes only text it can prove it added. The separate combined Astra/Ultrafast action retains confirmation because its speed command depends on selecting Astra first.

### Response speed

The two icons at the right are **Fast** (single bolt) and **Ultrafast** (double bolt). The Standard gauge has been removed; click the active Fast or Ultrafast button again to turn it off and return to Standard. Hover for the name. Fast and Ultrafast send `/fast` or `/ultrafast` as one complete Unicode text event, then press Return. They never read or write the clipboard, including when invoked through Agentic Mouse. They do not search, isolate or verify a command-menu entry, and do not backspace a rejected query. Like typing the command yourself, clicking an already active Fast or Ultrafast toggle returns to Standard. Codex handles the typed command and Return, including unsupported commands or an existing draft. The bar reports the requested speed, not proof that Codex applied it.

From 1.2.60 the icons also show the focused chat's speed on a best-effort basis: the active tier's bolt is filled in and tinted with the accent colour, and both stay outlined for Standard. Codex draws a small icon inside its model button only while Fast or Ultrafast is on, and the background poll reads that button anyway, so no icon means Standard. The two bolts expose identical Accessibility data. Each model's catalogue entry lists its faster tiers (`additional_speed_tiers`), and only GPT-6.1 Sol and GPT-6 Astra offer both, so other models' icon always means Fast. For those two, the bar first uses Codex's own saved choice: Codex writes every speed change, including a `/fast` or `/ultrafast` typed in Codex itself, to `service_tier` in `~/.codex/config.toml` (1.2.68). When that says Standard, it falls back to its own last command's tier, then assumes Ultrafast. The saved choice is global, so a chat whose speed was set before a later change in another chat can still show the other chat's bolt. Each command starts from what the icons showed, so its saved estimate follows the chat it was sent in. Right after a click the expected icon fills at once, and the next poll replaces it with what Codex shows.

Speed icons and mouse speed URLs use the same focus handoff. If Codex already identifies a focused chat input with a complete reciprocal parent/child path to its window, the bar uses that input directly instead of walking the message history twice. This also applies when Agent Flow temporarily owns the keyboard. Missing or flattened parent links use the existing child-tree lookup, which captures the intended Conversation before activation. Activation has no fixed pause; an input still mounting can wait up to 1.5 seconds inside that exact region, subject to the existing mouse expiry. Once the focus handoff finishes, both bar and mouse commands allow the input 100 ms to settle before typing. Speed lookup does not require a model button or a particular input placeholder, and never substitutes another pane or an embedded browser input. The bar remembers the original keyboard input and selection, briefly activates Codex, and uses the same AX focus and end-of-draft caret placement as Agent Flow’s click-to-focus helper. After posting the command, focus returns when another app or Agent Flow’s floating input originally owned it. A new external keypress or click cancels the handoff; changing apps prevents returning focus over the newer choice.

Fast and Ultrafast have no command readiness polling. After the 100 ms focus-settling pause, the complete command is sent in one key-down/key-up pair with a 10 ms interval, followed by the same 100 ms pause before Return. Return keeps its 30 ms down/up interval. This is one best-effort attempt, with no result detection, readiness polling or automatic retry. No clipboard snapshot, replacement or restoration is used. The bar never opens the picker or slash menu to discover speed, and never verifies a command; the model button's icon is only read passively for the display above. Button and mouse commands update one saved estimate only after text/Return is posted; repeated tier commands estimate Standard. The estimate is shared across chats and saved in `~/Library/Application Support/Codex Model Bar/speed.txt`, so it survives toolbar and Codex restarts. The file contains just the latest speed name plus a newline (at most 10 bytes); each update replaces it atomically, with no accumulating history. Commands made outside the bar, a model configuration change or a rejected command can leave it wrong; it is not confirmed Codex state.

`codex-model-bar://speed-up` inserts **one `/ultrafast` command**; `codex-model-bar://speed-down` inserts **one `/fast` command**. These mouse actions directly invoke Codex's toggles: repeating the already active command returns to Standard. They do not discover or step through tiers. The handler focuses the intended Codex input through the shared handoff before posting the command. Open the URLs with a nonactivating API so the handler can capture the original typing input.

Agentic Mouse sends `codex-model-bar://speed-cancel` on release to cancel later queued ratchets. The first ratchet is reserved as soon as it arrives, so a quick release cannot erase it while the Accessibility queue is busy. That reserved command may finish its text and Return while Codex stays active. Requests queued for more than 0.5 seconds are discarded; after two seconds from arrival an active mouse request cannot type or press Return. There are no command retries or confirmation queries. Rapid ratchets can therefore expire rather than replay later. Hardware input before admission cancels the action; a different keyboard-owning app before text/Return stops delivery. These fixed URLs cannot supply text, change models or force Astra.

### Mouse reasoning

From version 1.2.57, `codex-model-bar://reasoning-up` requests one higher reasoning level and `codex-model-bar://reasoning-down` one lower level. Agentic Mouse should open these in the background, just like the speed URLs, and send `codex-model-bar://reasoning-cancel` when the held gesture ends. All three URLs are fixed and reject extra paths, queries, fragments, credentials and ports.

Mouse reasoning and the slider share `ReasoningSwitcher`, including the same intended-pane discovery, question-card exclusion, `SpeedInputFocus` handoff, configured Codex shortcuts and keyboard-owner restoration. A ratchet presses Codex's increase or decrease shortcut once without reading the model or level; Codex itself stops at the first or last level. A new hardware key or click stops the action. Release cancels queued ratchets; an admitted action may finish, but no mouse shortcut is posted after two seconds, and a request waiting over 0.5 seconds is discarded. These limits match mouse speed actions and can drop rapid ratchets under lag instead of replaying them later. Nothing confirms the result; the watcher simply shows Codex's next label. Changing this app does not itself update Agentic Mouse's mappings.

The direct Unicode/Return event sources, clipboard preservation, cancellation, queued-release expiry, command descriptions, layout and button callbacks have automated coverage. The production double bolt was visually checked in an isolated native fixture, but that fixture lacked Accessibility permission for typing. The installed 1.2.26 paste flow was subsequently confirmed by the user to work faster and more reliably. Computer Use blocks direct Codex interaction in this environment; the reduced model/reasoning waits in 1.2.27 and the 1.2.28 background checks still need a real desktop check. Native desktop updates can change the command descriptions or keyboard handling.

## Limits and privacy

- The bar works with the macOS Codex desktop app. It uses the app's Accessibility tree, window list, bundled app-server and `/model` menu. Codex updates can change those interfaces and require a bar update.
- Accessibility access allows the app to inspect Codex's window and composer. The model switcher reads the draft before a search and when an abandoned search needs cleanup; the combined Astra action also reads it after choosing. The reasoning control reads the composer's model and effort title, and the speed icons read whether that button shows its speed icon. Speed buttons retain the original input’s selection and use the Codex input’s character count when placing its caret; they do not read draft text or verify speed afterward. It does not store chat text or include telemetry. It stores your hidden-button choices in macOS preferences and caches model names and supported effort levels locally in Application Support.
- Diagnostics stay on your Mac at `~/Library/Logs/Codex Model Bar/diagnostic.log`. They record app version, model/effort, opaque input and container identities, focus flags, lookup decisions, switch stages, timing and failure reasons. Ordinary model/reasoning actions record a request, not a confirmation. Toolbar focus handoffs record the original owner PID and whether restoration was confirmed. Confirmation for the combined Astra action records composer identity and replacement; abandoned-search cleanup records whether restoration was observed, text remains, or the draft was unreadable/changed. They exclude draft text, chat content, task titles and individual keystrokes. The current log and one previous log are each limited to 2 MiB and readable only by your macOS user. Include the relevant failure entries when reporting a problem; nothing is uploaded automatically.
- A switch can stop when Codex is not ready, its menu has changed, or you are actively typing. The strip reports the failure. If an abandoned search is still visible but cannot safely be removed, it tells you what remains. An unavailable or changed draft is recorded as unverified, not proof of leftover text. A request that finishes at Return is not a guarantee that Codex accepted it; the background watcher reports the actual selection.
- Source builds use your local signing identity. Public downloads pass Developer ID signing, Apple notarization and Sparkle feed signing before publication.

## Develop

`swift test --scratch-path .build.noindex` runs model parsing, title matching, draft-text, placement, composer-focus and stale-read tests, plus AppKit layout and slider-drag tests. `Sources/CodexModelBarCore` contains the pure logic. `Sources/CodexModelBar` contains the AppKit panel, Codex window tracking, model-menu interaction and reasoning shortcut control. `scripts/make-icon.swift` is the editable icon source. `LEARNINGS.md` records observed compatibility and testing lessons.

Contributions and issue reports are welcome. Please include the Codex desktop version and macOS version when reporting a model-switching problem, and remove personal task content from screenshots or logs.

## Release updates

Push app changes to main with a new `VERSION` and a higher integer `BUILD_NUMBER`. GitHub Actions runs the tests, builds both Mac architectures and records the source commit and archive hash. The private signing runner verifies that exact artifact, signs it with Developer ID, notarizes and staples it, then signs the update feed using its Keychain key. The workflow publishes a draft only after these checks, marks it latest and verifies the downloaded public bytes. Existing release tags are never overwritten. See `.github/workflows/release.yml` and `scripts/release-app.py`.

Release credentials stay on the signing Mac: a Developer ID identity, a notarytool profile selected by `NOTARY_PROFILE`, a Sparkle Keychain key for `com.ethansk.codex-model-bar`, and GitHub release access. The `codex-model-bar-release` runner must be online for publication; a source build alone does not publish an update.
